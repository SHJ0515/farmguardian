# 업무 규칙

## 사용 목적과 장치 공급

- 대상은 자기 농장 장치와 사진을 관리하는 네이티브 앱 사용자다. 취업 포트폴리오용 데모이며 로컬에서 실제 기능과 성능을 검증할 수 있어야 한다. 실제 고객 운영·과금 서비스는 현재 목표가 아니다.
- 물리 IoT 장치는 운영진이 렌탈하거나 판매하는 공급 장치다. 사용자가 외부에서 임의로 구매한 장치를 자율 연동하는 기능은 현재 범위에 없다. 렌탈·구매라는 공급 배경만으로 결제·계약·재고 관리 기능이 요구된 것은 아니다.
- 한 계정은 여러 물리 장치를 등록할 수 있다. 각 장치의 현재 소유 계정은 하나이며, 같은 장치를 여러 계정에 동시에 할당하지 않는다. 농장 구성원 사이의 공유 기능은 계획하지 않았다.
- 시리얼 번호 같은 식별자를 이용해 공급 장치를 등록하는 사용자 흐름을 지향한다. 식별자를 아는 것과 실물 장치의 등록 권한을 증명하는 것은 별개이며, 구체적인 보유 증명 방법은 미정이다.

## 계정과 장치의 생애주기

| 상황 | 현재 동작·확정 의도 | 남은 결정 |
| --- | --- | --- |
| 회원가입 | 일반 사용자로 가입하며 ‘직접 촬영’용 가상 장치를 자동 연결 | 이메일 정규화·인증·재가입 정책 |
| 물리 장치 연결 | 연결된 장치는 다른 계정이 다시 연결할 수 없어야 함; 계정당 1대 제한은 두지 않음 | 동시 등록의 원자적 처리와 등록 증명 방식 |
| 연결 해제 | 현재 소유자·별칭·작물·좌표를 비우고 연결 가능한 상태로 전환 | 양도·렌탈 종료를 나타내는 별도 이력의 필요성 |
| 직접 촬영 | 실제 IoT 장치가 없는 사용자도 앱 사진 분석을 사용할 수 있음 | 가상 장치의 일반 연결 해제 차단·탈퇴 후 처리 |
| 회원탈퇴 | 현재 계정을 소프트 삭제하고 연결 장치를 해제 | 사진·FCM 토큰·가상 장치 보존/삭제, 이메일 재사용 |
| 비활성 장치 | `INACTIVE` 값은 있으나 업무상 전이와 재등록 조건이 확정되지 않음 | 비활성화·해제 권한 및 연결 가능 조건 |

물리 장치와 직접 촬영용 가상 장치는 같은 개념이 아니다. 현재 저장 구조는 둘을 구분하는 종류 필드가 없으며, 가상 장치를 다른 계정으로 재등록할 수 있게 되는 문제는 해결 대상이다. 이를 정상적인 공유 기능으로 해석하지 않는다.

## 사진과 분석 결과

- 분석에 실패해도 이미 수신한 사진 정보는 남겨야 한다. 분석 결과가 없다는 이유로 사진 메타데이터를 함께 되돌리지 않는다.
- 분석이 성공한 뒤 푸시 발송이 실패해도 분석 결과는 보존한다. 사용자가 나중에 앱을 열면 저장된 결과를 확인할 수 있어야 한다. 알림 수신은 결과 보존의 조건이 아니다.
- 위 보존 규칙은 서버가 관리하는 사진 URL·크기·분석 결과에 관한 것이다. 외부 저장소 이미지 바이트의 보존 기간이나 탈퇴 후 보존 기간은 아직 정하지 않았다.
- 장치를 다른 사용자에게 넘겼다고 과거 사용자의 사진까지 새 사용자에게 귀속되게 해서는 안 된다. 현재 조회는 장치의 현재 소유자를 따라가므로, 생성 당시 소유자를 보존하는 구조와 기존 사진의 소유자 확인 절차가 필요하다.
- 기존 사진의 소유자를 확인할 수 없을 때 현재 장치 소유자로 임의 지정하지 않는다. 근거 확인, 격리·삭제 기준은 후속 설계에서 결정한다.

## 해충 판정과 알림

현재 분석 응답과 자동 알림은 각 탐지 객체의 신뢰도 항목 중 **0.2 이상**인 항목을 사용한다. 여러 해충 이름이 기준을 통과하면 각각 집계하므로 알림의 개수는 실제 개체 수와 항상 같다는 보장이 없다.

사용자는 향후 신뢰도를 **0.8 수준 이상**으로 높일 계획이다. 정확한 값, 경계 포함 여부, 판정 근거가 될 검증 이미지 집합은 미정이며 현재 적용값은 0.2다. 사진 상세 화면의 판정은 현재 저장된 `total` 값을 사용하므로, 임계값 변경 시 분석 응답·상세 표시·자동 알림의 의미를 함께 맞춰야 한다.

자동 해충 알림은 저장 결과를 알려주는 수단이다. 푸시 전달 실패를 분석 실패로 바꾸지 않되, 실패 표시·재발송·유효하지 않은 토큰 정리 방식은 아직 확정되지 않았다.

## 촬영 시간

야간 제한은 현재 꺼진 상태를 유지한다. **19시부터 다음 날 06시까지 제한한다는 의도와 기존 코드는 보존**한다. 이를 곧바로 활성화하거나 영구 폐지하지 않는다. 재활성화 시 사용할 시간대, 정확히 19:00·06:00인 시각의 허용 여부, 시험용 예외는 미정이다.

촬영 명령을 서버가 접수한 것과 장치가 촬영을 끝낸 것은 다르다. 명령 완료·실패를 사용자에게 어떻게 표시할지는 장치 응답 방식과 함께 결정해야 한다.
