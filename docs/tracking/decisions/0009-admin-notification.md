# 관리자 개별 알림은 기존 발송 계약을 유지한다

## 배경과 결정

기존 직접 발송 경로를 관리자 전용으로 옮기는 방향이 확정됐다. 사용자는 기존 입력·발송 응답을 유지하고 추가 제한·중복 제거·감사 설계는 확대하지 않기로 했다.

필수 제목·본문과 선택 사진 ID·URL·장치 ID를 유지한다. 추가 선택 필드 소유권/URL 검증·애플리케이션 발송 제한을 도입하지 않는다. 같은 요청을 다시 보내면 다시 발송한다. 수신자 토큰 없음과 현재 catch가 흡수하는 Firebase 오류는 기존 빈 200을 유지한다.

## 대안과 결과

- 전달 성공을 보장하는 응답, 중복 제거, 자동 retry·큐, 추가 업무 검증은 더 강한 계약이지만 사용자가 선택한 기존 동작 유지 범위에는 포함되지 않아 채택하지 않았다.
- 200은 전달 성공 보장이 아니며 잘못된 선택 데이터·중복 발송·추적 한계가 남는다. 인증·DTO 검증·DB 오류까지 성공으로 바꾸는 결정은 아니다.
- 새 관리자 감사 방식·보존 정책과 broadcast 개방은 보류다. 일반 사용자 토큰 기능·내부 자동 해충 알림에 ADMIN 제약을 전파하지 않는다. 토큰 원문 로그 문제를 해결했다는 결정도 아니다.
