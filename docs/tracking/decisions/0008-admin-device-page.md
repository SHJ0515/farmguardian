# 관리자 장치 목록은 고정 크기와 정렬을 사용한다

## 배경과 결정

기존 공개 AVAILABLE 장치 목록은 UUID·좌표를 포함했다. 사용자는 이를 관리자 기능으로 옮기고 제한된 페이지 조회로 제공하기로 했다.

AVAILABLE만 조회하고 기존 아홉 DTO 필드를 유지한다. Page 방식에서 20개 고정·ID ASC를 서버가 강제한다. 상태 필드 추가나 클라이언트의 크기/정렬 변경 허용은 결정하지 않았다.

## 대안과 결과

- 전체 배열 반환은 조회량이 장치 수와 함께 늘고, 클라이언트 임의 size/sort는 확정한 고정 계약과 맞지 않아 채택하지 않았다.
- 배열에서 페이지 응답으로 바뀌므로 관리자 화면의 파싱 계약 변경이 필요하다. Page JSON과 위반 size/sort를 거부할지 무시할지는 미정이다.
- 일반 사용자 장치 선택·등록 절차는 별도로 마련해야 한다. 관리자 조회를 장치 보유 증명으로 사용하지 않는다.
