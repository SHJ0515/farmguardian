# URL은 정확한 허용 목록과 기본 거부로 관리한다

## 배경과 결정

이전의 넓은 공개 경로는 인증이 필요한 Controller도 익명으로 실행할 수 있게 했다. 관리자·장치용 인증과 일부 소유권 검증은 아직 구현되지 않았다.

공개 네 경로와 사용자 열네 경로를 정확한 HTTP method/path로 허용하고 나머지는 거부한다. 기존 다섯 경로와 관리자 경로는 먼저 차단하고, 각 기능의 이관·인증이 준비되면 승인된 범위만 개방한다. 내부 ERROR와 `/error`가 동시에 맞는 경우만 오류 처리 예외로 둔다.

## 대안과 결과

- Controller에 principal이 있다는 이유로 넓은 `permitAll`을 유지하면 인증을 강제하지 못한다.
- 관리자라는 이유로 아직 미구현 경로를 먼저 열면 준비되지 않은 업무 경계가 노출되므로 채택하지 않았다.
- 기존 AVAILABLE 목록·IoT 분석·직접 알림·broadcast를 사용하던 소비자는 기능 공백을 겪는다. 관리자 목록은 안전한 사용자 장치 등록을 대신하지 않는다.
- HEAD·OPTIONS·상태 점검·미정의 method/path도 자동 허용되지 않는다. URL 인증 완료는 자원 소유권 검증 완료와 다르다.
