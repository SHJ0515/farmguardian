# Refresh 세션·이력과 재사용 탐지의 commit 경계를 유지한다

## 배경과 결정

옛 구조는 Refresh 원문을 저장했다. 현재는 같은 클라이언트 로그인 교체와 토큰 rotation·재사용 탐지·폐기를 구분하며, 동시 요청에서도 하나의 활성 세션과 현재 토큰을 유지해야 한다.

세션과 발급 이력을 분리하고 원문 대신 SHA-256 해시·jti·시각·상태를 저장한다. 사용자 → 세션 → 이력 순서의 비관적 잠금과 활성/현재 슬롯 UNIQUE를 사용한다. 재사용 탐지는 별도 TransactionService에서 폐기 기록을 commit한 뒤 외부 Service가 실패 응답으로 변환한다.

## 대안과 결과

- 원문 저장은 DB에서 credential을 직접 복원할 수 있고 발급 세대별 재사용 상태를 분리하지 못하므로 원문을 저장하던 옛 구조로 되돌리지 않는다.
- 폐기와 오류 발생을 하나의 rollback 트랜잭션에 넣으면 요청은 실패해도 세션이 살아남을 수 있어 채택하지 않는다.
- `@Version`만으로 바꾸는 것은 현재 잠금 전략의 단순 정리가 아니다. 변경하려면 경쟁·rollback 계약을 다시 검증해야 한다.
- 사용자 단위 잠금의 직렬화 비용이 있으며 슬롯 해제 UPDATE를 새 INSERT보다 앞서 보내는 flush 두 곳이 필요하다. V2 전환은 옛 Refresh 원문을 이관하지 않으므로 기존 사용자는 재로그인해야 한다.
