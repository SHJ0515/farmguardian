# 관리자 권한은 토큰과 현재 계정 상태를 함께 확인한다

## 배경과 결정

관리자 API 이관 정책은 확정됐지만 아직 구현·개방되지 않았다. 사용자는 최초 관리자 수동 지정과 관리자 요청마다 현재 DB 권한 확인을 선택했다.

관리자 기능은 JWT ADMIN, 현재 DB ADMIN, 미탈퇴 조건을 모두 충족해야 한다. DB 조회 실패·계정 없음은 허용하지 않는다. 역할 관리 앱/API는 만들지 않고 최초 지정은 수동으로 한다.

## 대안과 결과

- JWT 역할만 확인하면 발급 후 강등·탈퇴가 반영되지 않는다. DB 역할만 확인하면 기존 USER 토큰도 관리자 요청에 사용될 수 있어 두 조건을 함께 검사한다.
- 매 관리자 요청에 DB 비용이 발생하지만 일반 사용자 요청 전체에 같은 검사를 확대하는 결정은 아니다.
- 수동 승격 뒤에도 새 ADMIN 토큰이 필요하다. 역할 변경 시 Refresh 정리·기존 일반 Access의 폐기와 DB 오류의 구체 응답은 아직 미정이다. 관리자여도 사용자 API의 타인 자원 접근을 우회하지 않는다.
